Mandate

AI agents that negotiate, agree and settle money for you — inside rules you signed.

PayPal AI Hackathon 2026 PayPal Orders v2 · Payouts v1 · OAuth 2.1 · Live in Sandbox

Open with the simplest promise: Mandate separates asking from paying. In today’s demo, agents help a business move faster, but money only moves when a deterministic warrant allows it and, when required, the owner taps. This is not a wallet, not a new rail, and not a replacement for PayPal. It is a spend-authority layer in front of PayPal that turns every AI-assisted payment into a constrained, provable packet.

The insight & architecture · AI talks, code decides

The user who creates a payout cannot approve the same payout.

MATHEMATICAL SPEND GATE

Pure code decides. Zero model calls.

Every charge, payout and refund is evaluated by a pure function (`decide()`) against signed owner rules: payees, monthly caps, milestone limits, and funding coverage.

Invariant: AI may only add friction, never reduce it
ZERO-AUTHORITY AGENT DOOR

OAuth 2.1 (PKCE) + Mandate MCP

Agents sign in via browser with PKCE and owner console approval (`connection.approve`). They carry 13 tools: 8 that read context, 5 that propose, and zero that can pay or approve.

That is why we built Mandate. An agent can ask. The rules decide in code. Only Ananya can tap to pay, and PayPal moves exactly the cents locked. The key idea came from PayPal’s own Payouts approval model: the person who creates a payout cannot approve the same payout. That separation-of-duties principle is now programmable for AI agents. Our formal invariant: AI may only add friction, never reduce it. External agents connect via OAuth 2.1 with PKCE, carrying 13 tools and zero payment authority.

SPONSOR VALUE
AG Grid: Owner control room with CSV export & refusal filters
Render: Production hosting & public HTTPS for PayPal webhooks
Postman: One-click automated acceptance test suite
APIMatic: Verified OpenAPI 3.1 contract and SDK generation

The architecture connects PayPal's best rails behind a hardened authority layer. For client money in: Orders v2 with hosted card fields rendering on our own page and 3-D Secure verified server-side against PayPal. For contractor money out: Payouts v1 with idempotency keys derived from the lock hash so a network retry never double-pays. On identity: OAuth 2.1 with PKCE for agents, and WebAuthn Passkeys for owner biometric taps. Sponsors do real work: AG Grid powers the control room, Render hosts public webhook endpoints, and Postman automates our acceptance test suite.
